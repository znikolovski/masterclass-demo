# WKND — LLM / AI traffic tracking

How WKND measures **AI-driven traffic** on report suite **`ags050wknd`**. Companion to
[ANALYTICS-LAUNCH-PLAN.md](./ANALYTICS-LAUNCH-PLAN.md).

There are two distinct kinds of "LLM traffic", tracked by different mechanisms:

| Kind | Who | Runs JS? | Where it shows up |
|------|-----|:---:|-------------------|
| **AI referrals** | Humans clicking a citation/link out of an AI answer (ChatGPT, Perplexity, Gemini, Copilot, Claude) | ✅ Yes | **Adobe Analytics** (Web SDK) |
| **AI crawlers** | Bots (GPTBot, ClaudeBot, PerplexityBot, OAI-SearchBot, Google-Extended, …) | ❌ No | **CDN / edge access logs** only (or Adobe LLM Optimizer) |

> AI crawlers do not execute JavaScript, so the Web SDK never fires — they **cannot**
> appear in Adobe Analytics and are excluded by IAB bot rules regardless.

---

## Part 1 — AI referrals (Adobe Analytics)

### What the code already does (shipped)

[scripts/analytics-page.js](../scripts/analytics-page.js) detects AI-assistant referrers:

- On the landing hit it reads `document.referrer` and matches it against
  `AI_ASSISTANT_DOMAINS` (chatgpt.com, chat.openai.com, perplexity.ai, gemini.google.com,
  copilot.microsoft.com, claude.ai, you.com).
- The first match is persisted to `sessionStorage` (first-touch) so subsequent in-session
  page views keep the attribution even though `document.referrer` is then empty.
- On every Web SDK hit `mapPageToAnalytics` sets:
  - **`prop12`** = `ai-assistant` (channel flag)
  - **`eVar9`** = the assistant name (`chatgpt` / `perplexity` / `gemini` / `copilot` / `claude`)

This makes AI referrals segmentable in Workspace **immediately**, without admin access,
and with per-assistant granularity — independent of Marketing Channels.

### What YOU need to do in Adobe Analytics (admin)

Requires **Report Suite Admin / Marketing Channel Manager** on `ags050wknd` (the same
pending access noted in [ANALYTICS-LAUNCH-PLAN.md Phase 0](./ANALYTICS-LAUNCH-PLAN.md#phase-0--report-suite-admin)).

1. **Rename variables** — `Admin → Report suites → Edit settings`:
   - `prop12` (Custom Insight 12) → "AI Assistant Channel"
   - `eVar9` (Custom Conversion 9) → "AI Assistant Source" (allocation: Most Recent, expiry: Visit)

   > **Slot note:** `prop12` also appears in the 404/error-page mapping in
   > [ANALYTICS-LAUNCH-RUNBOOK.md](./ANALYTICS-LAUNCH-RUNBOOK.md) (`s.prop12 = page.errorUrl`,
   > marked "adjust slot to match admin"). AI-referral hits and error hits can both write
   > `prop12`; they overlap only when an AI-referred visitor lands on a 404. If that matters,
   > move the error-URL mapping to another free prop when you confirm the admin allocation.
2. **Marketing Channel processing rule** — `Admin → Marketing channels`, add channel
   **"AI Assistants / Generative AI"**:
   - Match **Referrer** / **Referring Domain** *contains any of*:
     `chatgpt.com`, `openai.com`, `perplexity.ai`, `gemini.google.com`,
     `copilot.microsoft.com`, `claude.ai`, `you.com`.
   - **Order it ABOVE Natural Search** — otherwise `gemini.google.com` and Bing-based
     Copilot get misclassified as search.
3. **Referring Domain classification** (fallback until the channel rule propagates):
   group the same domains under a classification value "AI Assistant".
4. **Workspace views**:
   - AI Assistants channel/`prop12` **trend** over time.
   - `eVar9` **breakdown** (which assistants send traffic).
   - AI-Assisted **segment** (`prop12 = ai-assistant`) stacked against **Adventure category**
     (`eVar4`) and **Journey stage** (`prop3`) — mirrors the segment patterns in
     ANALYTICS-LAUNCH-PLAN.md Phase 4.

**Without admin access:** report on `prop12` / `eVar9` (set client-side) or the standard
**Referring Domain** dimension — same [workaround](./ANALYTICS-LAUNCH-PLAN.md#phase-0--report-suite-admin)
as marketing channels generally.

### Generating demo data

The live traffic simulator has an **`ai`** marketing channel
([tools/scripts/lib/traffic-channels.mjs](../tools/scripts/lib/traffic-channels.mjs)):
each `ai` session lands with an AI-assistant referrer, so real Analytics visits are
produced and picked up by the client detection above.

```bash
# ~6% AI by default; or weight it up for a demo:
node tools/scripts/simulate-live-audience-traffic.mjs --from-index --channel-mix=ai:20,direct:40,organic:40
npm run simulate:traffic:dry   # preview the mix without sending traffic
```

## Part 2 — AI crawlers (edge logs)

Crawlers are observable only in **CDN / edge access logs** (or Adobe LLM Optimizer),
keyed on the bot **User-Agent** and the paths requested — especially `/llms.txt`
(generated by `npm run generate:llms`) and `/robots.txt`.

Report on them off the log source (not Analytics):
- Group by bot UA (GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, PerplexityBot,
  Google-Extended, CCBot, meta-externalagent, Applebot-Extended).
- Track crawl volume, most-crawled paths, and `/llms.txt` hit rate as an AI-visibility KPI.

### Generating demo data

```bash
npm run simulate:crawlers:dry              # preview
npm run simulate:crawlers -- --pages=40    # send AI-bot requests to the live edge
```

[tools/scripts/simulate-ai-crawler-traffic.mjs](../tools/scripts/simulate-ai-crawler-traffic.mjs)
drives plain HTTP requests with AI-bot User-Agents against `.aem.live`, hitting a sample
of query-index pages plus `/robots.txt` and `/llms.txt` per bot, and writes a run summary
to `tools/scripts/output/`. These hits appear in edge logs only — **not** in Analytics.
